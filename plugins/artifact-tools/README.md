# artifacts-manager

Claude plugin to query Stratio artifact repositories and trigger Jenkins builds.

## Installation

Install the plugin via the Claude Code CLI:

```bash
# Install for your user (all projects)
claude plugin install artifacts-manager@github

# Install for the current project only (shared with the team via .claude/settings.json)
claude plugin install artifacts-manager@github --scope project
```

During installation, Claude Code will prompt you for the required credentials:
- `GITHUB_TOKEN` — GitHub personal access token with read access to the Stratio org
- `JENKINS_USER` — Jenkins username
- `JENKINS_TOKEN` — Jenkins API token

## Available operations

### Search and explore artifacts

- Give me information about `gosec-management-ui`
- Search repositories for `gosec`
- What repositories are in the `rocket` and `gosec` scopes?
- What branches does `gosec-management-ui` have?
- Give me all versions of `gosec-management-ui`

### Versions

- What is the latest release of `gosec-management-ui`?
- What is the current snapshot of `gosec-management-ui`?
- What prereleases does `gosec-management-ui` have?
- What milestones does `gosec-management-ui` have?
- What is the next milestone I can generate for `egeo-navigation`?

Versions support both the standard format (`x.y.z`) and the combined universe+artifact format (`x.y.z-a.b.c`).
Milestones are recognized in both `x.y.z-M<n>` and `x.y.z-m.<n>` formats.

### Jenkins — generate builds

| Type | Example | Requirement |
|---|---|---|
| Prerelease | Generate a prerelease of `gosec-management-ui` version 1.5.0 | `branch-1.5` must exist |
| Milestone | Generate milestone 1.4.0 of `gosec-management-ui` | `branch-1.4` or master if version matches |
| Milestone (auto) | Generate a milestone of `gosec-management-ui` | Reads version from master automatically |
| Milestone (branch) | Generate milestone 1.4 of `gosec-management-ui` | Reads version from `branch-1.4` |
| Release | Launch release 1.5.0 of `gosec-management-ui` | `branch-1.5` must exist |
| Branch | Create branch 1.5 of `gosec-management-ui` (master will be set to 1.6) | — |

Jenkins operations automatically notify in the chat when the build finishes (success or failure). On failure, the extracted error cause and a direct link to the build execution are shown.

### Pull requests — merge and release

| Operation | Example | Notes |
|---|---|---|
| Check PR CI status | Is the CI passing on PR #42 of `gosec-management-ui`? | Uses `get_pr_pipeline_status` |
| Merge PR | Merge PR #42 of `gosec-management-ui` | Squash merge, bypasses branch protection. Requires admin token |
| Get PR info | What is the head branch of PR #42 of `gosec-management-ui`? | Uses `get_pull_request_info` |

## Skills `/`

| Skill | Usage | Description |
|---|---|---|
| `/artifact-latest-versions <name>` | `/artifact-latest-versions gosec-management-ui` | All versions for an artifact: snapshot, releases, milestones, prereleases and dev branch |
| `/scope-versions <keyword>` | `/scope-versions gosec` | Table with release, snapshot and prerelease for all repos matching the keyword |
| `/scope-versions SFE` | `/scope-versions SFE` | Same table for the predefined SFE scope |
| `/artifacts-manager-examples` | `/artifacts-manager-examples` | Quick-reference guide of everything the plugin can do |
| `/release-from-master <artifact> [subdirectory]` | `/release-from-master gosec-management-ui SFE` | Full release from master: create branch → wait CI → prerelease → wait CI → release. If subdirectory is omitted, asks at the start |
| `/merge-pr-and-release-from-master <pr-url> [subdirectory]` | `/merge-pr-and-release-from-master https://github.com/Stratio/gosec-management-ui/pull/42 SFE` | Waits for all PR checks to pass, squash-merges the PR (bypassing rules), then runs the full release-from-master flow |

## Development

### Setup

```bash
npm install
npm run build   # clean dist/ and compile TypeScript
npm run dev     # run with tsx without building (development)
npm start       # run the compiled server
```

For local credentials, copy `.env.example` to `.env` and fill in your values — this file is gitignored and never committed.

Changes in `src/` compile automatically via the hook configured in `.claude/settings.local.json`. After compiling, run `/mcp` in Claude Code to reload the server.

### Structure

```
src/
  mcp/
    index.ts          ← MCP server entry point
    github-mcp.ts     ← GitHub tools
    jenkins-mcp.ts    ← Jenkins tools
dist/
  mcp/                ← compiled output (generated by tsc)
skills/
  artifact-latest-versions/
    SKILL.md
  scope-versions/
    SKILL.md
    assets/scopes/    ← predefined scope lists
  artifacts-manager-examples/
    SKILL.md
  release-from-master/
    SKILL.md
  merge-pr-and-release-from-master/
    SKILL.md
.claude-plugin/
  plugin.json
```

### Testing skills locally

Skills in `skills/` are only loaded by Claude Code when the plugin is installed in another project. To test them while developing in this repo, create a symlink in `.claude/skills/` for each skill:

```bash
ln -s ../../skills/artifact-latest-versions .claude/skills/artifact-latest-versions
ln -s ../../skills/scope-versions .claude/skills/scope-versions
ln -s ../../skills/artifacts-manager-examples .claude/skills/artifacts-manager-examples
ln -s ../../skills/release-from-master .claude/skills/release-from-master
ln -s ../../skills/merge-pr-and-release-from-master .claude/skills/merge-pr-and-release-from-master
```

Add `.claude/skills/` to `.gitignore` so the symlinks are not committed. Then run `/reload-plugins` in Claude Code to pick up the skill.
